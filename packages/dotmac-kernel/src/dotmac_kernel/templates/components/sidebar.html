{# Admin sidebar nav. Phase 2b.1 Task 1 (findings F1/F5): this list is no longer hardcoded here — every entry comes from `nav_items` (a tuple of `app.core.features.NavItem`, collected from every ENABLED feature manifest's own `nav` sequence by `app.core.templating.install_surface_globals`, called once from `app/main.py`). A disabled feature's link simply isn't in `nav_items`, so it can never dangle here — this is THE fix for F5's "dead sidebar links when a feature is off". To add a sidebar entry, add a `NavItem` to that feature's OWN manifest (`feature.py`) — never add a link directly in this template. Highlighting is path-based (no `active_nav` context var needed anymore): an item is active if the current request path equals its `path`, or (for every path except the dashboard's bare "/admin", which would otherwise match as a prefix of literally every other admin path) the current path starts with `path + "/"` — so a nested route like a party's detail page (`/admin/parties/`) still highlights "People" (`/admin/parties`). Per-item icons were dropped along with the hardcoded list — `NavItem` only carries `label`/`path`(/`feature`), so every entry renders the same generic icon; a richer per-feature icon would mean extending `NavItem`, out of scope for this task. #}
