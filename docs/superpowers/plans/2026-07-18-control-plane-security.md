# Control-Plane Security Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax. Tasks respond 1:1 to Michael's adoption review items 1–5 (`docs/superpowers/reviews/2026-07-18-adoption-review.md`) and are step 1 of the module control-plane program (`.../2026-07-18-module-control-plane-directive.md` § Preferred sequence). Recon evidence (2026-07-18, all file:line verified): `require_platform` authenticates nobody and its only caller is the `/platform/tenants` router; `_is_platform_path` passes `/platform/*` on ANY host (`startswith` branch); `authenticate_request` is hard tenant-bound (returns None when `request.state.tenant is None`) so NO mechanism to authenticate a platform actor exists; `create_tenant` writes only the tenants row; first-admin bootstrap is a race-prone check-then-insert in tenant register; dev quickstart runs Postgres superuser (RLS bypassed); `unit_of_work.py` has zero production callers; password hashing is stdlib PBKDF2-HMAC-SHA256 (210k); no security-headers middleware; rate limiter is in-memory keyed on raw path (unbounded cardinality).

**Goal:** A platform control plane that is actually secured — independent platform-admin identity, exact-host platform routing, atomic audited tenant provisioning, deny-by-default tests — plus RLS-active development, a single transaction authority, and the security-baseline items that must precede the module control-plane program.

**Architecture:** Platform actors get their OWN identity tables (`platform_admins`, `platform_sessions`) and their own guard (`require_platform_admin`) — deliberately NOT tenant `Party`/`AuthSession` rows, which are tenant-bound by design (composite FKs, tenant-claim JWT). Platform routing is host-exact: `/platform/*` resolves ONLY on the configured `platform_root_domain`. Tenant provisioning becomes one transaction that creates tenant + owner party + credential + admin role + grant + audit trail, using `SET LOCAL app.current_tenant` on the platform session for the tenant-scoped writes (platform_api has no BYPASSRLS — the context must be explicit). The race-prone first-registrant-becomes-admin bootstrap is deleted; registration becomes an explicit policy setting. Dev runs RLS-active via the same three DB roles as production, verified by a dynamic catalog test. `unit_of_work.py` is deleted (stronger SoT rule: zero consumers → delete). Password hashing moves to Argon2id with legacy-hash upgrade-on-login. OIDC is NOT the default platform identity (starter can't assume an IdP) — the guard is a single seam a project can replace with OIDC; documented.

**Tech Stack:** existing stack + `argon2-cffi` (the one new dependency, per OWASP Password Storage guidance).

### Task 1: Platform identity + exact-host platform routing (deny-by-default)

**Interfaces produced:** `PlatformAdmin(id, email unique lower-indexed, password_hash, is_active, timestamps)`, `PlatformSession(id, admin_id FK, token_hash String(64), expires_at, revoked_at, timestamps)` — platform catalog tables, GRANT to `platform_api`/`app_admin` ONLY (REVOKE from `app_user`) in the same migration. `app.core.platform_auth.require_platform_admin(request, db=Depends(get_platform_db)) -> PlatformAdmin` — the ONE platform guard: (1) host must equal `settings.platform_root_domain` exactly (defense-in-depth with the middleware fix), (2) bearer token from `Authorization` header, validated JWT (separate `aud="platform"` claim so tenant tokens can never cross) + live `PlatformSession` row via the existing `hash_token` HMAC, (3) admin `is_active`. `POST /platform/auth/login` + logout: DECISION — platform auth endpoints live in `app/core/platform_auth.py` with a router mounted directly in `main.py`, NOT as a feature manifest (the manifest/capability model is for tenant capabilities; the platform surface must exist even with every feature disabled — document this rationale in the module docstring and ADR-0004). `scripts/create_platform_admin.py` bootstraps the first admin from CLI (platform DB creds required — same trust boundary as migrations; never an HTTP self-registration path).

### Task 2: Atomic tenant provisioning + platform audit + registration policy

- [ ] **Step 1 (RED):** `tests/test_tenant_provisioning.py` (Postgres): `POST /platform/tenants` (as platform admin) with `{slug, name, owner_email, owner_password}` → 201 AND, atomically: tenant row; owner `Party(person)` + `PartyPerson` + `UserCredential`; `admin` Role + `PartyRole`; TWO audit events under the new tenant (`platform.tenant.create`, `platform.tenant.owner_provision`) whose details name the platform actor's email — all verifiable via app_user session as that tenant. Failure atomicity: force a duplicate owner-email collision inside provisioning → NO tenant row remains (whole transaction rolled back). Owner can log in via `/auth/login` on the tenant host immediately.
- [ ] **Step 2:** Service: provisioning runs on the platform session; after `db.flush()` of the tenant row, `db.execute(select(func.set_config("app.current_tenant", str(tenant.id), true)))` (SET LOCAL semantics — same idiom as `get_db`) BEFORE the party/role/audit writes, because `platform_api` has no BYPASSRLS and those tables are FORCE-RLS. Owner creation needs party+credential writes, but `tenants` cannot import the `auth` feature (independence contract), and core owns no feature logic. DECISION: move `UserCredential` to `app/core/models.py` — it joins the other six identity models under ADR-0002's model-placement rule (models needed across feature boundaries live in core), making `tenants` provisioning compose core models only. Enumerate as PORT-DELTA in the commit + a new ARCHITECTURE ownership-table row. The `auth` feature keeps hashing/verification via `app.core.security`; nothing else about auth moves.
- [ ] **Step 3:** Delete `_assign_first_user_admin` + its callers; registration policy `SettingSpec` (`auth` domain, key `registration_policy`, string, allowed `{"open","closed"}`, default `"closed"`) read in `register` — closed → 403 `registration_closed`; provisioning is now the only owner-creation path; existing register tests updated (tenant fixtures provision an owner instead of registering-first). Document BREAKING (register no longer grants admin; default policy closed).
- [ ] **Step 4:** `GET /platform/tenants` gains `limit`/`offset` (bounded, clamp ≤200) — closes the unbounded platform listing now rather than waiting for the list_query envelope.

## Completion criteria

- An unauthenticated request cannot reach ANY `/platform/*` route from any host (Postgres canaries prove middleware + guard independently).
- One command sequence provisions a working tenant with a login-able owner and an audit trail, atomically.
- `make dev` runs with RLS enforced; the catalog test fails CI for any future table that forgets tenant_id/RLS/policy/grants/composite-FK or escapes alembic metadata.
- Exactly one transaction authority exists in the codebase and an AST governance test keeps it that way.
- Password storage is Argon2id (legacy upgraded on login); every response carries the security headers; SECURITY.md maps ASVS L2 honestly.
- Docs hierarchy live; ADR statuses truthful. Suites green; PR merged; v0.8.0.
